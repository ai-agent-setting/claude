에이전트 참조 문서 영문 정책

Claude가 컨텍스트에 로드해 읽는 참조 문서(가이드·스킬)는 전부 영문으로 작성한다. 동일 내용 기준으로 영문이 한국어보다 토큰 수가 적기 때문이다. 한국어 규칙(CLAUDE.md)은 사용자와의 응답 인터페이스에만 적용한다.

훅 & 알림

훅 작성 원칙: 훅은 매 이벤트마다 실행되므로 LLM 호출을 넣으면 토큰 비용이 누적된다. claude CLI, Anthropic API, MCP 도구는 훅 명령 안에 쓰지 않는다. 허용 범위는 osascript · jq · curl 같은 순수 셸 작업이다.
Stop
응답 완료 알림

긴 작업을 걸어두면 다른 창에서 다른 일을 한다. 그때 응답이 완료됐는지 확인하려고 터미널로 돌아오는 행동이 반복된다. 알림이 오면 그 왕복이 사라진다.

matcher: "" (모든 세션)
osascript -e 'display notification "답변이 완료되었습니다" with title "Claude Code"'
Notification
입력 / 허가 대기 알림

자동화 작업 중 Claude가 권한 프롬프트에서 멈춰 있어도 사용자는 모른다. 알림이 없으면 몇 분씩 멈춰 있는 세션을 뒤늦게 발견하게 된다.

matcher: ""
osascript -e 'display notification "Claude가 입력 또는 허가를 기다리고 있습니다" with title "Claude Code"'
PreCompact
컨텍스트 70% 도달 알림

대화 컨텍스트가 70%에 달하면 알림이 뜬다. 그대로 두면 자동 압축이 일어나 세션 흐름이 끊어지므로, /checkpoint로 미리 정리하도록 유도한다.

matcher: ""
osascript -e 'display notification "컨텍스트 70% 도달 — /checkpoint 실행 권장" with title "Claude Code"'
PostToolUse
편집 후 센티넬 파일 생성

Codex 리뷰 알림을 모든 세션에 보내면 노이즈가 된다. 질문·탐색만 한 세션에는 필요 없다. 실제로 코드를 수정했을 때만 리뷰 알림이 뜨도록 편집 여부를 파일로 기록한다.

matcher: Edit|Write
touch /tmp/claude_code_modified

PostToolUse → Stop 연쇄 패턴

1. Edit / Write 실행 시 touch /tmp/claude_code_modified
2. 세션 종료(Stop) 시 센티넬 파일 존재 여부 확인
3a. 파일 없음 → 응답 완료 알림만 발송 (코드 편집 없는 세션)
3b. 파일 있음 → 삭제 후 Codex 리뷰 권장 알림 추가 발송 
if [ -f /tmp/claude_code_modified ]; then rm /tmp/claude_code_modified && osascript -e 'display notification "/codex:rescue 로 리뷰를 실행하세요" with title "Codex 리뷰 권장"'; fi

알림 피로를 막는 게 핵심이다. 두 훅이 파일 시스템으로 상태를 공유해, 리뷰가 필요한 세션에만 추가 알림이 간다.

응답 규칙 & 한국어 글쓰기

응답 규칙

선제 질문 기준 (AskUserQuestion)

즉시 행동하는 경우: 요청이 명확하고 범위가 한정되어 있을 때, 이미 충분한 맥락이 대화에 있을 때.

먼저 묻는 경우:

  • 접근법이 둘 이상이고 선택에 따라 결과가 달라질 때
  • 범위가 모호할 때 (어떤 파일, 얼마나 깊이 편집할지)
  • 되돌리기 어려운 작업일 때

Surgical Changes (코딩 행동 규칙)

범위 밖 코드를 건드리면 의도치 않은 회귀가 생기고 리뷰 부담이 늘어난다. 변경 의도도 추적하기 어려워진다. 그래서 요청 범위 안에 든 줄만 수정한다.

죽은 코드를 발견하면 삭제하지 않고 언급만 한다. 자신의 변경으로 인해 불필요해진 import·변수·함수만 제거한다.

명령 출력 절감 (rules/command-output.md)

npm install 출력이 수백 줄이면 Claude가 이를 읽는 데 토큰을 낭비하고, 진짜 에러 메시지를 찾기도 어려워진다. 성공·실패 여부만 알면 충분한 경우가 대부분이다.

  • npm: --silent 또는 --loglevel=error
  • yarn: --silent · pnpm: --reporter=silent · pip: -q
  • 출력이 긴 명령: 2>/dev/null 또는 | tail -5

실패 시 에러 출력, 빌드 경고, 테스트 결과는 억제하지 않는다.

한국어 글쓰기 규칙

"결론적으로", 이모지, "~할 수 있다" 같은 패턴은 LLM 응답임을 즉각 드러내 글의 신뢰도를 낮춘다. 자연스러운 한국어처럼 읽히게 하려면 이 패턴들을 체계적으로 제거해야 한다. 10개 카테고리로 분류해 S1(무조건 제거)과 S2(3회 이상 등장 시 제거)를 구분했다.

카테고리 심각도 대표 패턴
A. 번역투S1~에 대해 / ~를 통해 / ~에 있어서 / 가지고 있다
B. 영어 용어 과다S2framework를 leverage하여 / 괄호 병기 남발
C. 구조적 AI 패턴S1첫째·둘째·셋째 전체 지배 / 이모지 남발
D. AI 관용구S1 (비재정의)결론적으로 / 시사하는 바가 크다 / 혁신적인
E. 문장 길이 균일S2모든 문장이 같은 길이 / 어미 4~5개 연속 반복
F. 과도한 수식S2매우 / 정말 / 대단히 / ~적 측면 / ~성 남발
G. 과도한 완곡S2~할 수 있을 것으로 보인다 (이중 헤징)
H. 접속사 남발S2또한 / 따라서 / 나아가 / 아울러 문두 반복
I. 형식명사 과다S2~한 것이다 / ~할 필요가 있다 / ~라는 것이다
J. 시각 장식 과다S2본문 bold 남발 / 대시(—) 남발

치환 예시

X에 대해 논의한다
X를 논의한다
X를 통해 Y한다
X로 Y한다 / X해서 Y한다
경쟁력을 가지고 있다
경쟁력이 있다 / 경쟁력이 강하다
높일 수 있다
높인다 (사실) / 높일 여지가 있다 (가능성)
합의가 이루어졌다
합의했다
~할 필요가 있다
~해야 한다

자동 작업 로그

Claude Code는 세션 간 컨텍스트를 공유하지 않는다. 다음 세션에서 "왜 그 결정을 했는가"를 알려면 기록이 남아 있어야 한다. Auto Memory는 상위 레벨 정보만 담으므로, 세부 경위와 트러블슈팅 내역은 로그가 맡는다.

worklog.md
신규 기능, 구조 변경, 버그 수정 등 의미 있는 완료와 설계 결정을 기록
troubleshooting.md
에러 증상 · 근본 원인 · 해결책을 세트로 기록
decisions.md
재사용 빈도가 높은 설계 결정과 그 근거 기록

커스텀 스킬

감사·리뷰 작업은 결과만 필요하다. 분석 과정을 메인 대화에 쌓으면 이후 작업에 쓸 컨텍스트가 줄어든다. fork 컨텍스트는 결과만 돌려받고, 메인 대화는 건드리지 않는다.

/checkpoint
현재 세션을 정리하고 로그에 기록한 뒤 재개 프롬프트를 출력한다. 컨텍스트가 길어졌을 때 /clear 전에 호출한다.
/review-claude-config fork
프로젝트의 Claude Code 설정 파일 전체를 베스트 프랙티스 기준으로 검토하고 점수화된 보고서를 출력한다.
/check-freshness fork
guides/ 파일의 last-reviewed 날짜를 확인해 경과 일수를 계산하고 오래된 파일을 감사한다.
/update-guides fork
공식 Claude Code 문서를 WebFetch로 가져와 로컬 가이드와 비교하고 업데이트를 제안한다.

플러그인

Claude 단독 판단보다 독립적인 관점이 필요할 때, 그리고 반복되는 CLI 명령을 외워두지 않고 자연어로 처리하고 싶을 때 설치했다.

codex@openai-codex v1.0.4
Claude가 작성한 코드를 Claude 자신이 검토하면 관점이 같아 사각지대가 생긴다. Codex에 위임하면 독립적인 시각에서 진단이 가능하다. 훅 연쇄로 코드 편집 세션 종료 시 자동으로 리뷰를 권장한다.
vercel@claude-plugins-official v0.42.1
배포·환경 변수·로그 조회에 쓰는 CLI 플래그를 매번 찾아보는 대신, /vercel:deploy · /vercel:status 같은 스킬로 의도를 바로 전달한다.
