현재 대화 컨텍스트를 바탕으로 세션을 정리하라.

---

# 실행 절차

## Step 1: 작업 유형 판단

현재 작업 디렉터리를 확인하라:

```bash
pwd
```

- 경로가 `~/.claude` 또는 `/Users/*/. claude` 하위이면 → **Claude Code 작업** → 로그 위치: `~/.claude/logs/`
- 그 외 프로젝트 디렉터리이면 → **프로젝트 작업** → 로그 위치: `[현재 디렉터리]/.claude/logs/`

로그 디렉터리가 없으면 생성하라:
```bash
mkdir -p [로그 위치]
```

## Step 2: 세션 내용 분석

현재 대화를 돌아보며 아래 항목을 파악하라:

- **작업 요약**: 이번 세션에서 완료한 작업들
- **미완료 태스크**: 시작했으나 끝내지 못한 것, 논의만 하고 실행하지 않은 것
- **다음 할 일**: 이어서 해야 할 구체적 스텝
- **오류 여부**: 오류가 발생했는가? 해결했는가?
- **결정 사항**: 설계·구조·방향에 관한 중요한 결정이 있었는가?

## Step 3: 로그 기록 (관련 파일만)

### worklog.md — 항상 기록

```bash
cat [로그 위치]/worklog.md 2>/dev/null || echo "(새 파일)"
```

파일 끝에 아래 형식으로 추가하라 (덮어쓰지 않음):

```markdown
## YYYY-MM-DD — [한 줄 제목]

### 완료한 작업
[구체적으로 무엇을 했는지]

### 미완료
[시작했으나 끝내지 못한 것]

### 주요 결정
[이번 세션에서 내린 결정 (없으면 생략)]
```

### troubleshooting.md — 오류가 있었을 때만

오류가 발생했고 해결 과정이 있었다면 기록하라:

```markdown
## YYYY-MM-DD — [오류 한 줄 설명]

**증상**: [오류 메시지 또는 현상]
**원인**: [파악한 원인]
**해결**: [적용한 해결책]
```

### decisions.md — 재사용 가치 있는 결정이 있을 때만

설계·아키텍처·방향에 관한 결정이 있었고, 나중에 다시 참고할 만한 내용이라면 기록하라:

```markdown
## YYYY-MM-DD — [결정 한 줄 설명]

**결정**: [무엇을 결정했는지]
**이유**: [왜 그렇게 결정했는지]
**대안**: [고려했지만 선택하지 않은 것]
```

## Step 4: 재개 프롬프트 출력

아래 형식으로 재개 프롬프트를 출력하라. 사용자가 `/clear` 후 다음 세션 첫 메시지로 붙여넣는다.

---

**세션 재개 컨텍스트 [YYYY-MM-DD]**

**작업 요약**
[이번 세션에서 한 일을 2~4문장으로 요약]

**미완료 태스크**
- [ ] [아직 끝나지 않은 것 1]
- [ ] [아직 끝나지 않은 것 2]
(없으면 "없음")

**다음 할 일**
1. [구체적 다음 스텝 1]
2. [구체적 다음 스텝 2]

---

## Step 5: 안내 출력

재개 프롬프트 출력 후 다음 메시지를 출력하라:

```
로그 기록 완료.
이제 `/clear` 를 실행하고, 위 재개 프롬프트를 첫 메시지로 붙여넣으세요.
```
